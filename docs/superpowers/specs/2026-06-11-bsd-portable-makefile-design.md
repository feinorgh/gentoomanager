# Portable multifile benchmark Makefile design

Date: 2026-06-11  
Status: Approved (design phase)

## Goal

Make the generated `compiler_multifile` benchmark project build reliably on BSD and Linux by using one portable Makefile, without changing benchmark intent or measurement comparability.

## Problem summary

Current generated Makefile uses GNU-specific variable expansion (`$(wildcard ...)` and GNU-style substitution), which is not handled consistently by BSD `make`. On BSD hosts this breaks object discovery and causes multifile link/build failures.

## Scope

In scope:

- Update `roles/run_benchmarks/files/generate_multifile_bench.py` to emit a portable Makefile.
- Preserve existing benchmark orchestration in `roles/run_benchmarks/tasks/compiler.yml`.
- Preserve current failure artifact behavior (`compiler_multifile_failure.json`, `benchmark_failure.json`, `benchmark_notes.json` failure append).
- Add/adjust unit tests for portability guarantees.

Out of scope:

- Changing benchmark command topology (still `make clean && make ... -j1/-jN`).
- Switching BSD hosts to `gmake`.
- Redesigning compiler benchmark categories outside multifile portability.

## Design

## 1. Portable Makefile strategy

Use an explicit source/object list generated by Python, instead of Make-time wildcard/substitution functions:

- `SRCS` will be emitted as a concrete list (`main.c mod_00.c ... mod_29.c`).
- `OBJS` will be emitted as a concrete list (`main.o mod_00.o ... mod_29.o`).
- Keep existing generic compile/link targets and recipes (`%.o: %.c`, `$(BIN): $(OBJS)`, `clean`).

This removes GNU-only parsing dependencies while keeping compile and link work equivalent.

## 2. Benchmark comparability

Comparability is preserved because:

- Same compiler executables are used.
- Same compile flags (`CFLAGS=-O2`) and parallelism (`-j1`, `-jN`) are used.
- Same source corpus and link target are used.
- Only Makefile expression mechanics are changed.

## 3. Error handling and diagnostics

No behavioral reduction in strictness:

- Multifile build failures remain hard-fail.
- Existing failure diagnostics and fetched artifacts remain intact.
- Portable Makefile change is intended to reduce false harness failures, not mask them.

## 4. Testing plan

Add or update unit coverage to assert:

- Generated multifile Makefile no longer contains GNU-only wildcard/substitution expressions.
- Makefile still contains expected targets (`all`, `clean`) and compile/link rules.
- Existing multifile integrity and failure-logging tests continue passing.

## Implementation notes

- Keep file changes surgical: generator + focused tests.
- Do not introduce OS branching in benchmark execution path for this fix.
- If portability edge cases remain, prefer extending the single portable template over adding BSD/Linux template split.

## Validation

- `uv run pytest tests/unit/test_multifile_harness_integrity.py`
- `uv run pytest tests/unit/test_multifile_harness_integrity.py tests/unit/test_benchmark_failure_logging.py`
- targeted benchmark rerun(s) for BSD compiler category to confirm multifile stage no longer fails for Makefile syntax reasons
